# Every tournament on at most 12 vertices is 5-inducible with unit margin (`n12_unit_margin/`)

**What it shows.** Every tournament on at most 12 vertices is the majority tournament of five voters
who carry every arc by exactly three votes to two (unit margin), so **N(5) ≥ 13**. We found unit-margin
five-voter witnesses for every tournament that is not 3-inducible up to n = 10, and for every tournament
up to n = 11. The 12-vertex tournaments, about 1.5 × 10¹¹ of them, would have been too many to
enumerate directly, so for n = 12 we extended each 11-vertex tournament by one vertex in all 2,048
possible ways and settled every extension. A profile restricted to a subset of the vertices keeps every
pairwise split, so the result at 12 vertices also covers every smaller order. Everything for this claim
is in this folder.

| order | what is settled here | how | where |
|---|---|---|---|
| 8, 9 | every non-3-inducible tournament (96 and 17,674) has an explicit unit-margin five-voter profile | the profiles are shipped and checked without the search that found them | `witnesses/` |
| 10 | the same for all 2,830,464 non-3-inducible tournaments; separately, every tournament is 5-inducible | the profiles are regenerated by the same search; an integer program decides each tournament | `witnesses/`, `ilp10/` |
| 11 | every non-3-inducible tournament (521,128,000 of D₁₁ = 903,753,248) has a unit-margin five-voter profile | constraint search over the whole catalogue, each profile rechecked by an independent verifier | `n11_census/` |
| 11, 12 | every tournament has a unit-margin five-voter profile | each 11-vertex tournament's unit-margin profiles are enumerated, and inserting a twelfth vertex into them covers its 2,048 one-vertex extensions | `n12_cover/` |

The three-voter part of the pipeline (deciding 3-inducibility, used to set aside the 3-inducible
tournaments at n ≤ 11) is the constraint search of the companion paper's census appendix; its source
is copied here so that this folder is complete.

## Subfolders

- `csp/` — the C engines.
  - `margin1_scan.c` decides 3-inducibility, and 3-inducibility with unit margin, as a labelling of
    the vertex triples (about 20 µs per tournament).
  - `cert_m1k5.c` searches for a unit-margin five-voter profile and writes it out as a labelling.
  - `verify_m1k5.c` rebuilds the five voters from each labelling, checks that each is a linear order
    and that every arc is carried exactly 3 to 2, and stops on any failure. It shares no code with
    the search.
  - `m1k5_profile.c` writes a labelling out as five explicit linear orders.
- `witnesses/` — the explicit profiles for n = 8 and n = 9 (`n8_unit_margin_profiles.txt.xz`,
  `n9_unit_margin_profiles.txt.xz`, about 260 KB together). Line k holds five orders (vertices
  from top to bottom) for the k-th non-3-inducible tournament of McKay's catalogue, in catalogue
  order. `verify_unit_margin.py` checks them with the Python standard library alone: every order is
  a permutation, every pair is split exactly 3 to 2, the majority equals the listed tournament, and
  the number of lines is the expected count; `check_witnesses.sh N` runs it against McKay's catalogue. `make_witnesses.sh` regenerates a file from a catalogue,
  and stops if any tournament has no unit-margin profile; the n = 10 file (40 MB) is not shipped.
- `ilp10/` — the integer program for n ≤ 10, in R with CPLEX (`solve_ilp10.R`, `ilp10_aggregate.R`,
  `make_chunks10.R`, with the shared helpers `ilp_realizability.R` and `Utilities.R`), and its
  CPLEX-free counterpart `verify_5inducible.py` (OR-Tools CP-SAT).
- `n11_census/` — the 11-vertex census: `n11_worker.sh` runs one slice of nauty's `gentourng`
  through `margin1_scan`, `cert_m1k5` and `verify_m1k5`; `n11_aggregate.sh` checks every slice and
  that the slice totals add up to D₁₁. Its README describes the run and its validation, and
  `RESULTS.md` holds the totals.
- `n12_cover/` — the 12-vertex analysis (the paper's appendix on order 12), run on a cluster.
  The scripts keep the paths of the cluster checkout they ran from
  (`KInduceDFS/jz_n12cover/`). `COMMANDS.md` lists the commands, `aggregate.sh` rolls the parts up and fails on any count that
  does not match, and `FINAL_ROLLUP.txt` is the roll-up of the completed run.
- `get_data.sh` — downloads McKay's catalogues for n = 8, 9 and 10 into `data/mckay/`, checking
  each file's size and line count.

## How to run

```sh
./get_data.sh                                   # n = 8 and 9 catalogues (~7 MB)
witnesses/check_witnesses.sh 8; witnesses/check_witnesses.sh 9   # checks the shipped profiles (seconds)

cd witnesses && ./make_witnesses.sh 9 ../data/mckay/tournaments9.txt 4   # regenerate n = 9 (seconds)
cd ../n11_census && seq 0 255 | xargs -P 8 -I{} bash n11_worker.sh {} 256 results bin "$(command -v gentourng)"
bash n11_aggregate.sh results 256               # the 11-vertex census, about 5.5 h on 8 cores
```

The 12-vertex analysis took 2,615.6 core-hours on a cluster; `n12_cover/COMMANDS.md` gives the
commands.

**Dependencies.** A C compiler; Python 3 (the standard library suffices for
`verify_unit_margin.py`; `ortools` for `verify_5inducible.py`); nauty's `gentourng` for the
11-vertex census; R with CPLEX's `cplexAPI` only for `ilp10/`.
